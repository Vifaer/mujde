# Mujde v1.2.0 使用说明

> 官方上游：https://github.com/mon231/com.rel.mujde  
> 本机改造源码：`frida-modules-dl/mujde-app/`  
> LSPosed 模块页：https://modules.lsposed.org/module/com.rel.mujde/  
> 包名：`com.rel.mujde`  
> 文档更新：2026-08-06（v1.2.0：Logs 桥 / 健康检查 / 反 Frida / Zygisk 导出 / CI）

## 1. Mujde 是什么

Mujde 是 **LSPosed 模块形态的 Frida 注入管理器**：

1. 维护本地 Frida JS 脚本库；
2. 为每个目标 App 勾选要注入的脚本；
3. 目标 App 加载后 Hook `Activity.onCreate`；
4. 广播到自身，再以 **root** 执行 `su -c libfrida-inject.so ...` 注入。

脚本语法是 **标准 Frida GumJS**，不是 LSPilot 的 Rhino / Java 插件。

**v1.1.x**：状态诊断页、应用内日志、脚本仓库下拉刷新/导入、已绑定 App 置顶、保存时自动申请 LSPosed 作用域、前台保活服务、钉死 Frida **17.16.4**。  
**v1.1.2 修复**：设备无 `sqlite3` 时用 Android SQLite 读/写作用域；寄生 LSPosed 打开；logcat 拉取不再因引号失败；脚本选择页高对比度文字。  
**v1.1.3**：同一 PID 多脚本合并为 **一次** `frida-inject`；「每进程只注入一次」真正可控；首页可调注入延迟；Apps 长按「立即注入」；脚本库 SAF 导入 `.js`/zip、导出 zip；清空绑定脚本时自动移出 LSPosed 作用域。  
**v1.2.0**：console→Logs 桥与实时刷新；健康检查与 Root 管理器引导；内置通用反 Frida（默认关）；导出 Zygisk/早注入配置；Gradle 自动拉 inject；模板向导；CI Release。

## 2. 安装

### 2.1 依赖

| 组件 | 说明 |
|------|------|
| Root | KernelSU / Magisk |
| Zygisk | ZygiskNext / NeoZygisk |
| LSPosed | Zygisk 版 |
| Mujde APK | `frida-modules-dl/mujde/Mujde-v1.1.2-debug.apk` |
| Root 授权 | **KernelSU 超级用户必须允许 `com.rel.mujde`** |

### 2.2 安装 APK

```text
adb install -r frida-modules-dl/mujde/Mujde-v1.1.2-debug.apk
```

### 2.3 LSPosed

1. 模块 → Mujde 打开  
2. 作用域勾选目标包（例：`com.zcs.udpmysteryforest`）  
   - v1.1.0 在 Apps 勾选脚本并保存时，可 **自动 root 写入 scope**（状态页开关「Auto-apply LSPosed scope」）  
3. 强制停止目标 App 后冷启动  
4. 建议打开一次 Mujde（前台通知「Injection listener active」），保证广播能送达  

### 2.4 KernelSU（本机关键）

Mujde 源码固定：

```text
ProcessBuilder("su", "-c", libfrida-inject.so + " -e -p " + pid + " -s " + script)
```

未授权时：状态页显示 `Root (su): DENIED`，日志页有 `Cannot run program "su"` / Permission denied。

处理：KernelSU → 超级用户 → 允许 Mujde（永久）。

### 2.5 Mujde 内配置

1. **Repository**：新建 / 导入 / 下拉刷新脚本  
2. **Apps**：已绑定包置顶 → 勾选脚本并保存（可触发作用域写入）  
3. **Logs**：查看注入 exit code / 拉 logcat  
4. **Status**：Frida 版本、su、脚本数、上次注入摘要  

Root 也可直接写入 `/data/data/com.rel.mujde/files/scripts/`，仍需 Apps 勾选。

## 3. 注入时机与模型

- 触发点：`Activity.onCreate` → 广播 → Mujde 以 root 执行注入  
- 默认 **每个进程只注入一次**（首页开关）；关闭后每次新建 Activity 都会再请求注入  
- 首页 **注入延迟**（0–10000 ms）：广播收到后延后执行，便于等 SO 加载  
- **多脚本**：按绑定顺序合并成一个临时 `.js`，对该 PID **只跑一次** `frida-inject`（避免二次挂 agent 失败）  
- **立即注入**：Apps 页对已绑定应用 **长按** → 对当前 `pidof` 结果强制注入（忽略「只注入一次」去重）  
- 局限：晚于首次 Activity 才加载的模块，仍须脚本内轮询 / `Interceptor.attach` 等待；「立即注入」也无法把时间点提前到进程创建  
- 脚本仍须：重入保护（`globalThis` 旗标）

## 4. 如何确认注入成功

```text
adb logcat -s Mujde:D
# 或打开 Mujde → Logs → Pull logcat / 看文件日志
adb shell "pidof <目标包名>"
```

成功标志：`about to frida-inject [...]` 且 `inject exit=0`。

且进程在注入数秒后仍存活；学习骨架应出现 `MF_LEARN` 日志。

> `console.log` 经 `frida-inject` 时**不一定**进 logcat。推荐用 `__android_log_write`（见学习骨架）。

## 5. 推荐学习路径（神秘元素消消乐）

| 顺序 | 脚本 | 目的 |
|------|------|------|
| 1 | `mysteryforest_learning_skeleton.js` | 验证注入存活（无 hook / 无 Java） |
| 2 | `mujde_hello.js` | 最小连通 |
| 3 | `mysteryforest_readonly_*.js` | 只读观测（按需，注意稳定性） |

货币逻辑在 `libil2cpp.so`；LSPilot Java 插件看不到该层。

## 6. SharedPreferences

应用↔脚本映射：

```text
/data/misc/apexdata/<GUID>/prefs/com.rel.mujde/mujde_prefs.xml
```

本机示例 GUID：`6c12afab-9ade-4b39-bf3b-68b6f8cc20d3`（会变）。一般用 App UI 勾选即可。
