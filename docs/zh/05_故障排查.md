# Mujde 故障排查

文档更新：2026-08-06（v1.2.0）

## 0. 先分清：没注入 vs 注入后闪退

| 现象 | 含义 |
|------|------|
| logcat / Logs 页无 `about to frida-inject` | 作用域/勾选/prefs / Mujde 未保活 |
| 有 `about to` + `Cannot run program "su"` / Status `Root DENIED` | **KernelSU 未授权 Mujde root** → 首页「打开 Root 管理器」 |
| 有 `about to`、`inject exit!=0` | frida-inject 失败（看 Logs 页 out） |
| 有 `about to`、进程马上死 | 脚本/Frida 把进程打崩；刚开反 Frida 激进档则先关 |
| 有 `about to`、进程活着、无脚本日志 | Logs「脚本console」或等自动吸入；检查 TAG |
| 启动即被杀 / 检测过早 | 晚注入赶不上 → 见 `06_场景矩阵与早注入.md` |
| 状态页作用域显示 0（实际已勾） | 旧版用设备 `sqlite3`；请升级 1.1.2+ |
| 拉取 logcat 失败 | 1.1.2+ 改为拉全量后 Java 过滤 |
| 打开 LSPosed 无反应 | 寄生管理器需 `com.android.shell/.BugreportWarningActivity`；1.1.2 已改 |

优先：**首页 → 一键健康检查**，再看 **Logs**。

```text
adb logcat -s Mujde:D MUJDE_SCRIPT:I MUJDE_ANTIFRIDA:I
adb shell "pidof <包名>"
adb shell "cat /data/local/tmp/mujde-console.log"
```

## 1. 模块开了但没注入

1. LSPosed：Mujde 开 + 作用域勾目标包（Apps 保存时可自动写 scope）→ 冷启动  
2. 打开一次 Mujde，确认通知「Injection listener active」  
3. Apps 勾选至少一个脚本  
4. 脚本在 `/data/data/com.rel.mujde/files/scripts/`（Repository 下拉刷新可见）  
5. 目标界面会走 `Activity.onCreate`  

## 2. `Cannot run program "su": error=13`

KernelSU（或其它）未给 `com.rel.mujde` 超级用户权限。  
处理：首页「打开 Root 管理器」→ 永久允许 Mujde → 冷启动目标。

## 3. 注入后闪退（SIGSEGV）

本机已复现原因：

1. **`Interceptor.replace` / `attach` 打在 8 字节短函数上**（如 `get_detectCheat` @ `0x6F65C0`）→ 踩坏相邻代码  
2. **`Java.perform` + Toast**（神秘元素消消乐）→ SIGSEGV  
3. Hook 改写返回值/控制流不当导致原生崩溃  

恢复：Apps 取消全部脚本，或 prefs 清空 `pref_app_scripts_map` 为 `{}`，冷启动。

验证注入请用：`mysteryforest_learning_skeleton.js`（无 hook、无 Java）。

## 4. 脚本列表看不到新文件

```sh
su -c 'ls -la /data/data/com.rel.mujde/files/scripts/'
# 必要时：chown 为 Mujde 应用 uid；chmod 644
```

强制停止 Mujde 再开 Scripts 页刷新。

## 5. 语法 / 引用错误

- 混入 LSPilot Rhino API  
- 在非 Frida 宿主用 `Process`  
- 无重入保护重复 attach  

先跑学习骨架 / `mujde_hello.js`。

## 6. `libil2cpp.so` 找不到

用 `setTimeout` 轮询等待；确认 IL2CPP + arm64。

## 7. 日志刷屏 / 卡顿

去掉高频 hook；补重入 flag。

## 8. Mujde App 闪退

无 LSPosed / 模块未激活时常见。先保证 LSPosed 正常。

## 9. 改了脚本没生效

改官方目录、冷启动、Apps 仍勾选该文件；Mujde 不读 stderr，失败时只看 logcat。
